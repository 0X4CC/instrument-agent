
## 三、注册流程（五步）

### 步骤 1 · 登录（账号不存在会自动注册）

```bash
uv run acps-cli --config acps-cli.toml auth login \
  --username <你的用户名> \
  --password '<你的密码>' \
  --name "科研仪器智能运维" \
  --org-name "科研仪器智能运维项目组"
```

**参数说明**：

| 参数 | 用途 |
| --- | --- |
| `--username` / `--password` | 平台账号；**不存在会自动注册** |
| `--name` | Agent 的显示名（自动注册时用） |
| `--org-name` | 组织名（**别写学校名**） |

**成功标志**：返回 token，并写入 `./.acps-cli/tokens/registry-user.json`。

**验证**：

```bash
uv run acps-cli --config acps-cli.toml auth whoami
```

---

### 步骤 2 · 保存 Agent 草稿

```bash
uv run acps-cli --config acps-cli.toml agent save \
  --acs-file partners/online/instrument_diagnosis/acs.json \
  --json
```

**必须看到返回的 `agent-id`（一个 UUID），下一步要用。**

> ⚠️ **`acs.json` 里 `aic` 字段现在是空的**——这是对的，**审核通过后平台才分配 AIC**。

**如果报错**，通常是 `acs.json` 结构问题。先跑测试：

```bash
uv run pytest tests/test_data.py -q
```

---

### 步骤 3 · 提交审核

```bash
uv run acps-cli --config acps-cli.toml agent submit \
  --agent-id <步骤 2 返回的 UUID>
```

**提交后就进入人工审核队列。**

**查状态**：

```bash
uv run acps-cli --config acps-cli.toml agent list --json
```

> 🔑 **提交后不要干等**——继续做技术报告、演示视频。**审核可能几小时，也可能几天。**

### 步骤 4 · 审核通过 → 领证 ✅（2026-10-28 已完成）

**审核通过后**，`agent list` 里能看到 AIC（形如 `1.2.156.3088.1.1.XXXXXX.XXXXXX.1.XXXX`）。

```bash
# 1) 取 EAB 凭据
uv run acps-cli --config acps-cli.toml cert eab fetch \
  --aic <你的 AIC> \
  --output ./keyfiles/eab.json --json

# 2) 申请证书（两个用途都要：serverAuth 给自己当服务端，clientAuth 给对方验你）
AIC="<你的 AIC>"

uv run acps-cli --config acps-cli.toml cert issue \
  --aic "$AIC" --eab-file ./keyfiles/eab.json \
  --usage serverAuth --key-type ec \
  --key-path "./keyfiles/private/$AIC.key" \
  --cert-path "./keyfiles/certs/$AIC-server.pem"

uv run acps-cli --config acps-cli.toml cert issue \
  --aic "$AIC" --eab-file ./keyfiles/eab.json \
  --usage clientAuth --key-type ec \
  --reuse-key \
  --cert-path "./keyfiles/certs/$AIC-client.pem"
```

> ⚠️ **实测踩过的坑**：`cert issue` 的默认输出路径对两个用途是**同一个文件**
> （`certs/<AIC>.pem` + `private/<AIC>.key`）——不指定路径的话，第二次签发会**覆盖**
> 第一次的证书和私钥。**必须像上面那样**：第一张给 `--key-path` 落盘私钥，
> 第二张用 `--reuse-key` 复用同一把私钥，证书各存各的路径。

**产物落在** `./keyfiles/`：

```
keyfiles/
├── eab.json                      ← 注册凭据（.gitignore 已挡）
├── private/<AIC>.key             ← 私钥，两证共用（.gitignore 已挡）
├── certs/<AIC>-server.pem        ← serverAuth 证书（给 uvicorn 当 HTTPS 服务端）
├── certs/<AIC>-client.pem        ← clientAuth 证书（我们调别人时证明身份）
└── trust-bundle.pem              ← 平台 CA 信任链（验证对端证书用）
```

**验证**：`openssl x509 -in certs/<AIC>-server.pem -noout -text` 里
`Extended Key Usage` 应为 `TLS Web Server Authentication`，client 那张为 `TLS Web Client Authentication`。

> 🔴 **`eab.json` 和 `.key` 绝不能进 Git**——`.gitignore` 已经挡住了，**别手动改**。

## 四、⚠️ 最大的坎：平台怎么访问到你的 Partner？

平台在公网，你的服务在本机 `localhost:8011`。**中间需要一条通路。**

| 方案 | 做法 | 难度 | 适合 |
| --- | --- | --- | --- |
| **A. 内网穿透** | frp / ngrok / cpolar 把 8011 映射到公网 | 中 | **最现实** |
| **B. 云服务器** | 买台学生机，把 Partner 部署上去 | 中 | 有预算 |
| **C. 只在本地演示** | 不接平台，仅本地双进程 | 低 | **但过不了"平台验证"门槛** |

> 💡 **问平台方**：有些比赛会提供**统一的部署环境**或**内网穿透支持**。**问 QQ 群 1102086449 或培训时直接问**——这比你自己折腾快。

## 六、常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `uv add acps-cli` 解析失败 | 它要 `acps-sdk>=2.2.0`，PyPI 没有 | **先装 git 版 acps-sdk**（见第一节） |
| `auth login` 401 | 账号密码错 / 平台地址错 | 核对 `acps-cli.toml` 的 `base_url` |
| `agent save` 报 acs 结构错 | JSON 字段缺失或类型不对 | 跑 `pytest tests/test_data.py` |
| `agent submit` 报 agent-id 无效 | UUID 抄错 | 重新 `agent save` 拿新的 |
| 审核一直 pending | 人工审核，正常 | 每天 `agent list` 查一次，别干等 |
| 证书申请失败 | EAB 过期 / AIC 不对 | 重新 `cert eab fetch` |
