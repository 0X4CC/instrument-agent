>
> 最后更新：2026-10-20

## 一、`data/faults.json` —— 故障规则库

**一句话**：**一条规则 = "看到这个错误码 + 这个传感器超标 → 就是这种故障"。**

### 1.1 字段表

| 字段 | 类型 | 必填 | 填什么 |
| --- | --- | --- | --- |
| `code` | 字符串 | ✅ | **错误码**，如 `"E-201"`。**原样照抄仪器屏幕上的** |
| `device_type` | 字符串 | ✅ | **设备类型**，如 `"离心机"`。必须和 `instruments.json` 里的 `device_type` **一字不差** |
| `name` | 字符串 | ✅ | **故障名**，如 `"转子不平衡"`。给维修人员看的 |
| `severity` | 字符串 | ✅ | **严重度**：`"低"` / `"中"` / `"高"` / `"紧急"` |
| `checks` | 对象 | ⬜ | **佐证条件**：`{"传感器字段": 阈值}`，实际值 **>** 阈值才算佐证。**不填就只看错误码** |
| `cause` | 字符串 | ✅ | **可能原因**，由谁引起 |
| `action` | 字符串 | ✅ | **处置建议**，具体到"停机检查什么" |
| `manual` | 字符串 | ⬜ | **手册位置**，如 `"§3.2 转子平衡与维护"` |

### 1.2 一个完整例子

```json
{
  "code": "E-201",
  "device_type": "离心机",
  "name": "转子不平衡",
  "severity": "中",
  "checks": { "vibration_mm_s": 5.0 },
  "cause": "转子配重不均，或离心管放置不对称",
  "action": "停机，检查转子配重块与离心管对称性；重新配平后低速试运行",
  "manual": "§3.2 转子平衡与维护"
}
```

**读法**：

> 看到 `E-201`（离心机）**并且** 振动值 `> 5.0 mm/s` → **确诊"转子不平衡"**，严重度中。
> 如果振动值 `≤ 5.0` → **降级为"疑似"**（报错了但数据不支持）。

### 1.3 `checks` 怎么用

**`checks` 是"传感器佐证"——它让诊断从"查表"变成"判断"。**

```json
"checks": { "vibration_mm_s": 5.0 }
```

| 实际振动值 | 结论 |
| --- | --- |
| `8.2` | ✅ **确诊**（8.2 > 5.0） |
| `3.1` | 🟡 **疑似**（3.1 ≤ 5.0，数据不支撑） |
| 没上报 | 🟡 **疑似**（无法佐证） |

**一个规则可以写多个 `checks`（全部通过才算确诊）**：

```json
"checks": {
  "vibration_mm_s": 5.0,
  "rotor_temp_c": 10.0
}
```

> **什么时候不写 `checks`？**
> 有些故障**没有可用的传感器数据**（比如"箱门未关严"只能靠门磁）。
> **那就只凭错误码判断**——`"checks": {}` 或者整个字段省略。

### 1.4 ⚠️ 常见错误

| ❌ 错误 | ✅ 正确 | 为什么 |
| --- | --- | --- |
| `"device_type": "离心机"` 但 instruments 里写 `"离心"` | **两边必须一字不差** | 匹配不上就永远找不到规则 |
| `"checks": {"vibration_mm_s": "5.0"}` | `"checks": {"vibration_mm_s": 5.0}` | **阈值必须是数字**，不是字符串 |
| 字段名写成 `"vibration"` | `"vibration_mm_s"` | **必须和 instruments 的字段名一致** |
| 两个规则用同一个 `code` + 同一个 `device_type` | 合并成一条，或用 `checks` 区分 | 后一条会被跳过 |

## 二、`data/instruments.json` —— 仪器状态

**一句话**：**每台仪器一条记录，记录它"现在"的状态。**

### 2.1 字段表

| 字段 | 类型 | 必填 | 填什么 |
| --- | --- | --- | --- |
| `id` | 字符串 | ✅ | **唯一编号**，如 `"CEN-01"` |
| `name` | 字符串 | ✅ | **显示名**，如 `"高速冷冻离心机 A-01"` |
| `device_type` | 字符串 | ✅ | **必须和 faults.json 里的一字不差** |
| `model` | 字符串 | ⬜ | 型号 |
| `vendor` | 字符串 | ⬜ | 厂商 |
| `status` | 对象 | ✅ | **当前状态**（见下） |

### 2.2 `status` 里的字段

**这些是"传感器读数"——不同仪器上报的字段不一样，用不上的可以不写。**

| 字段 | 类型 | 哪类仪器用 | 什么含义 |
| --- | --- | --- | --- |
| `running` | 布尔 | 全部 | 是否在运行 |
| `error_code` | 字符串/null | 全部 | **当前错误码；正常就写 `null`** |
| `vibration_mm_s` | 数字 | 离心机 | 振动速度（mm/s） |
| `rotor_temp_c` | 数字 | 离心机 | 转子温度（°C） |
| `speed_rpm` | 整数 | 离心机 | 转速 |
| `lamp_hours` | 整数 | 分光光度计 | 光源累计使用小时 |
| `baseline_drift_abs` | 数字 | 分光光度计 | 基线漂移（吸光度） |
| `wavelength_error_nm` | 数字 | 分光光度计 | 波长误差（nm） |
| `temp_deviation_c` | 数字 | 培养箱 | 温度偏差（°C） |
| `humidity_rh` | 数字 | 培养箱 | 湿度（%RH） |
| `door_open_seconds` | 整数 | 培养箱 | 箱门已开时长（秒） |

> ⚠️ **要加新传感器字段？**
> **必须同时改两处**：① 这个 JSON ② `diagnose.py` 里的 `仪器状态` 模型。
> **否则 Pydantic 会忽略新字段**（默认 `extra="ignore"`）。

### 2.3 一个完整例子

```json
{
  "id": "CEN-01",
  "name": "高速冷冻离心机 A-01",
  "device_type": "离心机",
  "model": "Eppendorf 5424R",
  "vendor": "Eppendorf",
  "status": {
    "running": true,
    "error_code": "E-201",
    "vibration_mm_s": 8.2,
    "rotor_temp_c": 4.1,
    "speed_rpm": 12000
  }
}
```

## 三、两个文件怎么对上

```
instruments.json               faults.json
     │                              │
     │  device_type: "离心机"        │  device_type: "离心机"
     │  status.error_code: "E-201"  │  code: "E-201"
     └──────────────┬───────────────┘
                    ▼
              匹配成功 ✅
                    │
                    ▼
        用 status 里传感器值去比 checks 的阈值
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
      全部超标             有没超标的
       确诊                  疑似
```

**三个必须对齐的点**：

1. **`device_type` 字符串完全一致**
2. **`error_code` 和 `code` 完全一致**
3. **`checks` 里的字段名，必须是 `status` 里真实存在的字段**

## 四、怎么去找真实数据

**按这个顺序问**：

### ① 问师哥 / 实验室

| 问什么 | 为什么要 |
| --- | --- |
| **仪器型号、厂商** | 决定 `model` / `vendor` |
| **故障码表**（哪怕拍照） | **这是最值钱的**——`code` 直接抄 |
| **常见故障有哪几种** | 决定写几条规则 |
| **每种故障参考手册哪一节** | 填 `manual` |
| **有没有传感器读数**（历史记录 / 导出日志） | 决定 `checks` 能不能用 |

### ② 翻仪器手册

**大部分工业仪器的说明书里都有"故障代码表"**，通常是一张表：

```
代码     含义                     处理方法
E-201    Rotor imbalance          检查配平
E-202    Temperature error        ...
```

**照抄就行。**

### ③ 拿不到就构造——但要说清楚

**构造数据不丢人，假装是真实数据才丢人。**

构造的时候守三条：
- **数值要在物理上说得通**（离心机转速不会 50000 rpm）
- **故障码格式要像真的**（别用 `"故障1"` 这种）
- **在 README / 答辩时明说"目前是构造数据，接口已预留"**

## 五、填完之后怎么验

```bash
cd "D:/Privacy Docs/study/agent/instrument-agent"
uv run python diagnose.py
```

**看到这三种情况，说明数据是对的**：

| 看到的 | 说明 |
| --- | --- |
| ✅ 没有 `WARNING ... 未收录在规则库中` | 所有错误码都能匹配到规则 |
| ✅ 结论有"确诊"也有"疑似" | `checks` 阈值设置得合理（不是全过也不是全不过） |
| ✅ 汇总里各类都有 | 数据覆盖面够，演示效果好看 |

**如果全都是"未知故障"** → `device_type` 或 `error_code` 对不上，逐条查。
**如果全都是"确诊"** → `checks` 阈值太低，没有区分度，演示时看不出"疑似"的价值。
